# STM32F767 CANopen (CiA 301 / CiA 401) Reference Example

This turnkey example demonstrates running the CANopen protocol stack on an **STM32F767** (e.g., NUCLEO-F767ZI) or custom industrial automation controller board at **500 kbps**.

---

## 1. Features
- **CiA 301 Communication Profile**:
  - Boot-up message on power-up/reset (`COB-ID 0x700 + NodeID`, payload `0x00`).
  - NMT slave state machine (`Initialisation` -> `Pre-Operational` -> `Operational` / `Stopped`).
  - Heartbeat producer (`0x1017`, default 1000 ms period).
  - SDO server supporting both expedited (1..4 bytes) and segmented upload (strings, e.g., `0x1008` device name).
- **CiA 401 Generic Automation I/O Profile**:
  - `0x6000 sub 1`: 8 Digital Inputs mapped to **TPDO1** (`COB-ID 0x180 + NodeID`).
  - `0x6200 sub 1`: 8 Digital Outputs / Relays mapped to **RPDO1** (`COB-ID 0x200 + NodeID`).
  - `0x6401 sub 1..4`: 4 Analog Inputs (16-bit) mapped to **TPDO2** (`COB-ID 0x280 + NodeID`).
  - `0x6411 sub 1..2`: 2 Analog Outputs (16-bit) mapped to **RPDO2** (`COB-ID 0x300 + NodeID`).
- **CanFestival `objdictgen` Compatibility**:
  - Uses native CanFestival `subindex` and `indextable` data structures.
  - Directly load dictionaries generated by `gen_cfile.py` (Python 2 or Python 3 fork).

---

## 2. Hardware Wiring (CAN Transceiver)

The STM32 internal CAN peripheral (bxCAN) requires an external 3.3V CAN transceiver (e.g., **SN65HVD230**, **TCAN334**, or 5V **MCP2551** with level shifter).

| Signal | STM32F767 Pin (Default) | Alternate 1 | Alternate 2 | Transceiver Pin |
|---|---|---|---|---|
| CAN1_RX | **PD0** | PB8 | PA11 | RXD / R |
| CAN1_TX | **PD1** | PB9 | PA12 | TXD / D |
| GND | GND | GND | GND | GND |
| 3.3V | 3V3 | 3V3 | 3V3 | VCC |

Ensure the CAN bus has a **120 \(\Omega\)** termination resistor at each end of the trunk.

## 3. Baud Rate & Clock Timing Calculation

CANopen standard bit rate is **500 kbps**.
- On STM32F767 running at 216 MHz SYSCLK:
  - APB1 peripheral clock = **54 MHz**.
  - Nominal Bit Time: \(\text{Bitrate} = \frac{f_{\text{APB1}}}{\text{Prescaler} \times (1 + \text{TS1} + \text{TS2})}\)
  - With **Prescaler = 6**, Nominal Bit Time = \(18 \, T_q\):
    - `Sync_Seg` = \(1 \, T_q\)
    - `TS1` = \(13 \, T_q\) (`CAN_BS1_13TQ`)
    - `TS2` = \(4 \, T_q\) (`CAN_BS2_4TQ`)
    - `SJW` = \(1 \, T_q\) (`CAN_SJW_1TQ`)
    - Bit rate = \(\frac{54\,000\,000}{6 \times 18} = 500{,}000 \, \text{bps}\).
    - Sample point = \(\frac{1 + 13}{18} = 77.78\%\) (CiA 301 recommends 75% – 87.5%).

## 4. CanFestival `objdictgen` Workflow

To create and integrate custom object dictionaries:

1. **Create/Edit the dictionary** in GUI or text format using [chenyurong22/objdictgen](https://github.com/chenyurong22/objdictgen) (Python 3):
   ```bash
   python objdictedit.py
   ```
2. **Generate C source code**:
   ```bash
   python gen_cfile.py MyBoardNode.od MyBoardNode.c
   ```
3. **Integrate into application**:
   In `MyBoardNode.c`, `gen_cfile.py` exports `const indextable MyBoardNode_objdict[]`.
   Wrap it in `canopen_od_t`:
   ```c
   #include "MyBoardNode.h"
   #include "canopen/canopen.h"

   static const canopen_od_t g_custom_od = {
       MyBoardNode_objdict,
       sizeof(MyBoardNode_objdict) / sizeof(MyBoardNode_objdict[0])
   };

   int main(void) {
       can_driver_init(500000U);
       canopen_init(&g_canopen_node, 1, &g_custom_od, can_driver_transmit);
       can_driver_filter_config(1);
       can_driver_start();

       while (1) {
           canopen_process(&g_canopen_node, 1);
           HAL_Delay(1);
       }
   }
   ```

## 5. Quick Verification with Linux SocketCAN

```bash
# 1. Bring up CAN interface at 500k
sudo ip link set can0 type can bitrate 500000
sudo ip link set up can0

# 2. Monitor frames
candump can0

# Expected on power-up (Node ID = 1):
# can0  701   [1]  00               (Boot-up)
# can0  701   [1]  7F               (Heartbeat Pre-Operational every 1000ms)

# 3. Start Node (Enter Operational):
cansend can0 000#0101
# Expected Heartbeat changes:
# can0  701   [1]  05               (Heartbeat Operational)

# 4. Write Digital Outputs via RPDO1:
cansend can0 201#5A

# 5. Read Device Name via SDO:
cansend can0 601#4008100000000000
# Response:
# can0  581   [8]  41 08 10 00 16 00 00 00  (Segmented Initiate: 22 bytes)
```
